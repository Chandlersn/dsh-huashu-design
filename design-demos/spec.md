# 花叔设计插件 UI 优化共同输入

日期：2026-11-11。范围：已安装的 DSH `dsh-huashu-design` 插件。本文是设计分析的共同内容契约；运行时代码与 upstream 本次不修改。

## 目标、对象与交付语义

目标是让使用者在 DSH「花叔设计」原生面板中先理解可创作的媒介与真实风格，再编写需求、生成草稿、带草稿进入新对话。受众是需要制作网页、幻灯片、信息图、App 原型、动画视频、小红书图文，或评审已有设计的中文创作者。

下一阶段的三个方向应是**原生已安装插件中的可切换完整初稿**：同一 `main` 插槽、同一真实目录和业务动作，通过 A/B/C 方向切换比较。三版都覆盖创作、风格、作品、流程、指南及草稿状态；最终选择前展示三版，不能把某一版暗中当作定稿。用户此次仅委托本 agent 写分析文件，因此本文不声称三个界面已经实现、已截图或已通过视觉验收。无需创建替代站点、伪宿主、独立服务器或第二个应用根节点。

92 风格来自网页 20、PPT 20、信息图 20、App 12、中文与东亚 12、小红书 8。风格分组不是任务分类：`ppt` 对应任务 `deck`，`info` 对应 `infographic`，`xhs` 对应 `xiaohongshu`；`east` 是跨媒介参考，不能直接作为任务发送。动画、评审没有专属风格分区，须允许不选风格。

## 共同比较内容与尺寸

三版默认任务统一为「网页与原型」，需求输入统一为空，风格初始为「让内容决定方向」，作品均为空。比较操作时使用测试输入「为花叔设计插件整理一个以真实样张为入口的创作面板」，这是测试需求文本，不是已完成作品。三版至少共用以下样张：网页 `web-13-glassmorphism-bento`、网页 `web-17-functional-brutalism`、App `app-01-hardware-panel`、东亚 `east-05-hanzi-experimental-poster`。需要额外样张时继续取 catalog 的真实 `specimenUrl`，不画假作品补位。

目标尺寸统一为宿主浏览器视口 1440×900、375×812；面板实际可用宽度会扣除宿主导航，桌面布局应按容器可用宽度降级，而非仅依赖全窗宽。桌面与手机都要完成整个面板流程，不能只做首屏展示。

## form 五问：共同答案

| 问题 | 答案与内容依据 |
|---|---|
| 叙事角色 | 创作入口与检索工作台；第一屏回答「能做什么、可参考什么、如何开始」 |
| 观众距离 | 笔记本约 50–80cm，手机约 25–40cm；桌面正文至少14px，375正文建议16px |
| 视觉温度 | 操作区冷静、准确；样张区保留上游真实题材的丰富度。兴奋感由素材承担 |
| 容量估算 | 7任务不做7张同规格大卡；92风格须搜索/分类/分页；4流程作为步骤资源；0作品诚实留空 |
| 视觉母题 | 同一创作方法横跨不同媒介，样张的长宽比、题材和版式差异就是母题；不额外套档案柜、地铁图、终端等道具 |

form 来自内容的哪里：这是一个有 92 张真实风格样张、7 种创作任务、4 条方法流程的创作工具，适合让图像展示、需求编辑和目录定位分别成为三版的主线。

## 功能与边界

维持现有业务契约：`catalog` 读目录、`list` 读作品、`read` 读文档、`draft` 准备未发送草稿，作品登记/移除沿用现有动作。只有用户主动点击「带草稿打开新对话」才调用既有 `ctx.uiWorkspace.startSession(undefined,{prompt:draft})`；该按钮不应声称自动发送。切换方向不调用这些写动作，不清空已写需求，不丢失草稿、任务、风格或检索状态。

保留真实错误提示、重试、空结果、分页、加载、请求取消、作品移除确认与“仅移除登记记录，原文件保留”的说明。中英文可见文案继续走 locale；资料原文保留原文。文档不要作为没有层级的长 pre 淹没主工作流：可使用现有 read 结果分区/折叠，但不能捏造宿主不存在的渲染服务。
